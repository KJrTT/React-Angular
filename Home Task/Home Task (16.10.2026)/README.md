# Документация: Выполнение упражнений по React

В ходе работы были выполнены упражнения из Частей 3 и 4. Весь код был собран в одном файле `App.jsx` без использования внешних CSS-файлов и сторонних библиотек. Стилизация (там, где она необходима по условию задачи) реализована через инлайн-стили React.

---

## Часть 3: Состояние и события

### 1. Счётчик с шагом
Создан компонент `StepCounter`. 
- **Состояние:** `count` (текущее значение) и `step` (шаг).
- **Реализация:** Кнопки `+` и `-` используют функциональное обновление состояния `setCount(prev => prev ± step)`, чтобы избежать ошибок при быстрых кликах. Шаг задается через управляемый инпут (controlled component).

### 2. Переключатель темы
Создан компонент `ThemeSwitcher`.
- **Состояние:** `isDark` (boolean).
- **Реализация:** При клике на кнопку состояние меняется на противоположное. В зависимости от состояния формируется объект `themeStyle` с инлайн-стилями (изменяется `backgroundColor` и `color`), который применяется к контейнеру.

### 3. Форма логина
Создан компонент `LoginForm`.
- **Состояние:** `email` и `password`.
- **Реализация:** Используются управляемые инпуты. Вычисляется производная переменная `isValid` (оба поля не пустые), которая управляет атрибутом `disabled` у кнопки. При отправке формы вызывается `e.preventDefault()` для предотвращения перезагрузки страницы и выводится `alert`.

### 4. Список покупок
Создан компонент `ShoppingList`.
- **Состояние:** `items` (массив объектов с покупками) и `inputValue` (текст из инпута).
- **Реализация:** Добавление новой покупки создает новый массив через спред-оператор `[...prev, newItem]`. Удаление реализовано через метод `.filter()`. Каждому элементу списка задан уникальный `key`.

## Часть 4: Списки, условия и Todo-приложение

Для выполнения упражнений этой части было собрано Todo-приложение (компоненты TodoForm`,`Filters`,`TodoItem`).

### 5. Фильтр по приоритету
- **Реализация:** Добавлено состояние `priorityFilter`. При вычислении списка `visibleTodos` к существующей фильтрации по статусу (active/done) добавлена проверка `t.priority === priorityFilter`. В интерфейс добавлен `<select>` для выбора приоритета.

### 6. Сортировка
- **Реализация:** Добавлено состояние `sortBy` (значения `'date'` или `'alpha'`). Массив задач копируется через `[...visibleTodos]` (чтобы не мутировать состояние) и сортируется. Для алфавитной сортировки используется `localeCompare`, для сортировки по дате — разница `id` (так как `id` генерируется через `Date.now()`).

### 7. Поиск
- **Реализация:** Добавлено состояние `searchQuery`. Массив фильтруется с помощью метода `.includes()`, при этом и текст задачи, и запрос приводятся к нижнему регистру через `.toLowerCase()` для регистронезависимого поиска.

### 8. Счётчик выполненных (прогресс-бар)
- **Реализация:** Вычисляется процент выполненных задач. В JSX добавлен нативный HTML-тег `<progress>`, которому передаются атрибуты `value` (выполненные) и `max` (всего задач). Если задач нет, `max` равен `1`, чтобы избежать ошибок деления на ноль.

### 9. Редактирование с валидацией
- **Реализация:** В компоненте `TodoItem` добавлено локальное состояние `isEditing`. При сохранении текст обрезается через `.trim()`. Если результат пустой — выводится `alert`, сохранение отменяется, и компонент остается в режиме редактирования. В ином случае вызывается колбэк `onEdit` от родителя.

### 10. Массовые операции
- **Реализация:** В `TodoApp` добавлены три функции:
  - `markAllDone`: перебирает массив через `.map()` и ставит `done: true`.
  - `deleteCompleted`: фильтрует массив, оставляя только задачи с `done: false`.
  - `clearAll`: запрашивает подтверждение через `window.confirm` и очищает массив задач.
  Вызываются через соответствующие кнопки в интерфейсе.
